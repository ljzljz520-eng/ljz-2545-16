# ADR 001：路线卡采用服务端统一版式，而不是浏览器打印样式

- 状态：已采纳
- 日期：2026-10-01
- 适用范围：徒步路线打印卡的单页 PDF 生成、预览、归档和下载

## 背景

路线卡必须在 A4 或 Letter 标准纸张的单页内保持可读，且要同时满足：

1. 起终点、退出点、注意事项不能被静默丢弃。
2. 长路线不能靠把字体缩小到不可读来硬塞。
3. 厕所/饮水核对时间、用时估算依据和过期“待确认”状态必须稳定输出。
4. 卡片要注明路线版本和信息日期。
5. 生成中的路线更新不能改变任务内容。
6. 文件不得包含网站导航、地图图像或私有编辑字段。

浏览器 `@media print` 依赖用户浏览器、PDF 引擎、字体可用性、页边距设置和分页实现。即使屏幕预览正确，也可能在不同 Chrome/Safari/Edge 或系统字体下出现分页、字体替换和缩放差异。

## 决策

采用服务端生成任务：

1. 网页只负责选择路线版本、步行方式、字段和明确摘要规则。
2. 提交前调用服务端容量估算接口。
3. 服务端使用同一个 `src/layout.js` 内容模型测量高度并渲染 PDF。
4. 最小正文字号固定为 9pt，不提供“自动缩小到能塞下”的选项。
5. PDFKit 自动新增页面被禁用；最终渲染若越过单页边界，任务失败而不是产出多页文件。
6. 创建任务时冻结：公开路线内容、选择字段、步行方式、摘要规则、纸张、版式版本、容量估算和原始来源元数据。
7. 后台 worker 从 PostgreSQL 拉取 `queued` 任务；服务重启会把 `rendering` 重置为 `queued`，任务可恢复。
8. HTML 预览由同一批冻结内容/内容块生成，仅用于展示服务端版式，不承担最终分页责任，也不提供浏览器打印 CSS 作为替代。

## 摘要规则

- `full`：完整卡片。溢出时拒绝提交。
- `key_turns`：保留强制安全信息、用时、里程/爬升和关键拐点；折叠地标、应急、交通等并在卡片列明。
- `safety_minimal`：安全最小卡。保留起终点、退出点、注意事项、用时和关键厕所/饮水；列明被折叠内容。

## 后果

### 优点

- 分页和字体可重复，服务端内置 Noto Sans SC，避免字体缺失。
- 验收可直接检查 PDF 页数、字号下限、版本/日期、私有字段和图片。
- 任务与路线版本绑定，生成中路线发布新版本不会影响已冻结任务。
- 撤回路线时，可以把既有任务链接标记为过期。

### 代价

- 需要 Node 服务、PostgreSQL、后台 worker 和持久化文件卷。
- 版式变更要显式升级 `layoutVersion` 并重新生成。
- 预览不是浏览器原生打印设置的完全替代；这是有意选择，因为最终事实来源是服务端 PDF。

## 不做的方案

- 不使用全站页面加 `window.print()`。
- 不输出地图图片或截图。
- 不提供窄纸张/热敏纸等不能承载安全信息的纸张。
- 不通过“任意缩小字号”解决长路线溢出。
