# ADR 001：采用服务端统一版式渲染 PDF

## 状态
已采纳。

## 背景
路线打印卡必须在不同浏览器和纸张设置下保持一致，并且要在提交前判断单页 A4 是否溢出。浏览器打印样式依赖用户的打印对话框、缩放、字体、页边距和分页实现，难以在服务端给出可靠容量承诺。

## 决策
- 最终交付物由 Node.js + PDFKit 在服务端渲染为单页 A4 PDF。
- PDFKit 使用随应用安装的 Noto Sans SC Regular/Bold，并嵌入字体文件，避免中文字体缺失。
- 提交前用同一字体度量生成布局预算；不通过自动缩小字号解决溢出。
- 预览 HTML 由服务端按同一份冻结/待生成内容模型输出，使用固定 A4 像素比例和同一字体，仅用于核对内容；它不是最终排版依据。
- 打印卡不使用地图图像、网页导航或其它装饰性大图。

## 后果
所有客户端取得的 PDF 版式一致；容量判断可复现。代价是服务端需要维护 PDF 与 HTML 两个渲染器，因此两者均只接收同一 allowlist 内容模型。
